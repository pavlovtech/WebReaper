← back to the terminal

CONCEPT

WebReaper's headline claim is that the whole scraper fits in one ~12 MB binary you run from a shell. So the site refuses to be a website: it is the shell. A single full-viewport CRT — P1 green phosphor, scanlines, a slow refresh sweep — boots a fake BIOS, prints an MOTD, and hands you a live prompt. Every product fact is a command you run, not a section you scroll. The register is literal: monospace because it is a terminal, green because it is a tube.

WHAT'S REAL

  • Transcripts marked "recorded from a real run" were captured from the actual v11.3.2 release binary on 2026-07-10 — including webreaper scrape https://webreaper.ai reaping its own homepage, map, init, and version (which honestly prints 11.3.1+…, because 11.3.2 was an MCP-satellite-only release).
  • The bot-protection ladder transcript is labeled simulated — the ladder itself (HTTP → browser → stealth, host-sticky floor, blocked pages dropped, non-zero exit) is the real documented ADR-0083 behavior.
  • Nothing scrapes live from the page; typing a novel URL tells you so and points at the install command instead.

IMPLEMENTATION

  • One static HTML file, zero dependencies, ~30 KB. A hidden input drives the prompt; output is a role="log" aria-live region.
  • Command router with history (↑/↓), TAB completion, ctrl-L, aliases, easter eggs (cowsay, sudo, exit = CRT power-off collapse).
  • theme amber swaps the whole phosphor palette via CSS custom properties on data-theme — P1 green and P3 amber, like real tubes.
  • CRT optics are layered pseudo-elements: corner vignette, 3px scanline raster, a 9s refresh sweep, and a rare flicker keyframe. New lines land bright and settle — phosphor persistence as a CSS animation.
  • Typography: VT323 (a digitization of the DEC VT320 glyphs) — the one case where "terminal font" is the register, not a costume.

ACCESSIBILITY & PERFORMANCE

  • prefers-reduced-motion kills the boot animation, sweep, flicker, cursor blink, and typing effects — everything prints instantly.
  • Suggested-command chips are real buttons (mobile users never need the keyboard); focus-visible outlines; noscript fallback carries the full pitch and install commands.
  • One font, no JS libraries, no images. First paint is the boot screen.

ITERATION LOG

  • Pass 1 — structure. Boot felt slow (2.8s) and the banner overflowed at 375px: cut boot to ~1.2s + skip-on-input, added a compact two-line banner under 640px, moved chips into the log flow so they scroll with history.
  • Pass 2 — optics & type. Scanlines were muddying small glyphs: raster dropped to 14% opacity and body size raised; dim-green contrast lifted from 3.9:1 to ≥4.6:1; glow reduced on body text and reserved (strong) for the banner and cursor.
  • Pass 3 — honesty & detail. Every transcript re-checked against captures; added the recorded-run date stamps, the version footnote, the "replays recorded runs" footer note; exit animation rebuilt as clip-path collapse; TAB completion pool widened to aliases.

REPRODUCE THIS

1. capture ground truth:   download the release binary, run
   scrape/map/init under `script -q /dev/null`, save stdout+stderr
2. write the command table first (content), theme second (optics)
3. one CSS variable set per phosphor; test both at 375/768/1440px
4. verify: axe pass, reduced-motion pass, keyboard-only session
5. deploy: static directory → `vercel deploy --prod`
