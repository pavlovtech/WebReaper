CREATIVE DIRECTION

The sibling concepts dress WebReaper up (a terminal, a workbench, a newspaper). This one refuses the costume and shows the domain itself: what a crawl is. The site is the operations console a fleet supervisor would watch at 03:00: a crawl graph growing out of a seed URL, a frontier draining, an escalation ladder lighting up, host floors pinning, records streaming to sinks, and a RunReport when the outstanding-work latch trips. Aesthetic lane: LED ops wall, near-black blue with one amber primary and strict signal colors (HTTP slate, browser amber, stealth violet, alarm red, ok green). Barlow Condensed for labels, JetBrains Mono for data. No decoration that isn't telemetry.

WHAT'S REAL (AND WHAT'S SIMULATED)

The console is a deterministic simulation: a seeded PRNG grows a fictional shop.example; nothing is fetched. It says so persistently, in the graph header and the footer badge. What is not invented is every behavior the simulation performs:

  • Per-page escalation on block markers, browser summoned with no flag (ADR-0083), stealth by consent (WEBREAPER_AUTO_STEALTH=1).
  • Host-sticky floors: the first confirmed block lifts the host's floor; the run pays the climb once. The HOST FLOORS table shows exactly this.
  • Honest failure: one page stays blocked at the top tier, is dropped (red ✕ on the graph, never counted as a record), and the run concludes with exit 1. The RunReport overlay mirrors RunAsync returning a RunReport.
  • The agent scenario is sequential by design, decide → persist → execute over a durable run store, with LLM calls counted as brain decisions (ADR-0051). The clean sweep shows LLM CALLS 0, because the deterministic pipeline costs nothing.
  • The fleet panel's claim is the library's real seam story: .WithRedisScheduler(...) / .TrackVisitedLinksInRedis(...) / Azure Service Bus let workers share one crawl.
SIMULATION — the numbers are synthetic; the semantics are documented product behavior, cross-checked against the v11.3.x binary's help text and the repository README.

IMPLEMENTATION

  • One static HTML file. The console is a CSS grid of panels around a 2D canvas; the crawl graph is a radial tree (rings by depth, angle jitter by seeded PRNG), redrawn each tick with a radar sweep and fresh-node pulses.
  • The simulation is a small engine: a frontier queue, an in-flight set with per-tier load times, tier floors per host, a hard-blocked page, and an outstanding-work-latch conclusion. Scenarios (CLEAN SWEEP / BOT WALL / AGENT RUN / INJECT BLOCK) just parameterize it; the same seed always replays the same run.
  • The loop is a setInterval paced by wall-clock deltas, not requestAnimationFrame: rAF is suppressed in some embedded panes and throttled tabs, and a wall-clock interval burst-catches-up instead of freezing. (Found the hard way; the first build sat at zero forever inside a preview pane.)
  • prefers-reduced-motion fast-forwards the whole run synchronously and renders the final state: same story, no animation.
  • Zero libraries, two fonts, no images; the favicon is an inline SVG radar.

ACCESSIBILITY & PERFORMANCE

  • The event log is a role="log" live region; scenario buttons carry aria-pressed; the report is role="status"; the canvas has a descriptive label and every fact it shows also exists as text in the panels.
  • Body text ≥ 7:1 contrast; signal colors are never the only carrier (tier counts and floor names are spelled out).
  • ~110 nodes on a 2D canvas at 30 fps is negligible; the page is one request plus fonts. With scripts off, a noscript block states the product facts and links out.

ITERATION LOG

PASS 1 · STRUCTURE & LIVENESS

First screenshot showed a perfect shell and a dead sim: the pane suppresses rAF entirely. Replaced the loop with a wall-clock-paced interval (and removed the document.hidden gate that would have frozen it in embedded contexts); fixed inner panel headings (HOST FLOORS, AGENT LOOP) that were falling through to default h2 styling.

PASS 2 · BEHAVIOR VERIFICATION

Drove all scenarios programmatically and asserted the state machine: BOT WALL produced the detect → climb → climb → floor-pinned-at-STEALTH sequence, exactly one dropped page, and an exit-1 RunReport (86 pages, 22/4/60 by tier); AGENT RUN produced five sequential decisions, five brain-decision LLM counts, one record, durable-resume note; INJECT BLOCK fired mid-sweep. Also re-paced the site model (branching widened, loads slowed) after the first sweep finished in nine seconds with a thin tree.

PASS 3 · SMALL FORMATS & POLISH

375 px pass: the grid collapses to stacked panels, scenario buttons wrap, the graph keeps a 340 px stage, code rows scroll internally; log texture improved (per-section parse lines with sizes instead of repetitive sink lines); console clean of errors across all scenarios.

REPRODUCE THIS WORKFLOW

1. write the semantics down first (FACTS.md): what climbs, what pins,
   what drops, what the report carries: the sim may invent numbers,
   never behavior
2. build the engine before the skin: seeded PRNG, frontier, tiers,
   floors, latch; make every scenario a parameter of one engine
3. skin it as telemetry: panels = claims, log = narrative, graph = proof
4. pace by wall-clock deltas (interval, not rAF); fast-forward for
   reduced motion
5. verify by driving the UI programmatically and asserting the states
6. deploy the directory: vercel deploy --prod
